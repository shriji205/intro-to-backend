# Intro to Backend

A beginner-friendly character-post API built step by step with JavaScript ES Modules, Node.js, Express, MongoDB Atlas, Mongoose, dotenv, and bcrypt. Nodemon is used only during development.

## What Phase 1 teaches

Node.js runs JavaScript outside a browser. npm installs packages and runs commands listed in `package.json`. A dependency is another package our application uses.

`express` handles HTTP requests and responses. `mongoose` defines schemas and talks to MongoDB. `dotenv` loads values from `.env` into `process.env`. `bcrypt` hashes passwords and compares submitted passwords with hashes. `nodemon` watches source files and restarts the server during development, so it belongs in `devDependencies`.

`package.json` records what the project needs. `package-lock.json` records the exact dependency tree npm resolved, including packages used by our direct dependencies. `node_modules` contains the installed package files; recreate it with `npm install`, or use `npm ci` when a committed lockfile is available.

`"type": "module"` tells Node.js to interpret `.js` files as ES Modules. We will use `export` to share values and `import` to use them in another file, with `.js` extensions in relative import paths.

`npm start` runs `node src/index.js`. `npm run dev` runs `nodemon src/index.js`. Neither command creates the application code for us; `src/index.js` is added in Phase 3.

The configured Node.js version is 24 LTS. Keep the lockfile under version control and keep `.env` and `node_modules` out of it. Login will verify credentials only; this tutorial will not introduce tokens, sessions, or cookies.

## Phase 2: MongoDB Atlas connection

### Create the Atlas database

1. Open https://www.mongodb.com/cloud/atlas/register and create or sign in to your MongoDB Atlas account. Verify your email if requested. Atlas screen labels may vary.
2. Create a project named `Intro to Backend` and open it.
3. Choose to create a cluster and select the Free tier (often labelled M0). Avoid paid Dedicated or Flex options for this tutorial. A cluster is the database deployment that hosts your databases.
4. Choose an available region close to your backend. For development in India, choose Mumbai if offered on the free tier; otherwise choose a nearby available region such as Singapore. Confirm the selected tier is free before creating the cluster.
5. Under Database Access (sometimes under Security > Database & Network Access), create a password-based database user. This is separate from your Atlas website account. Give it the `readWrite` role for `intro_to_backend` using a database-specific role if available. Use a strong generated password and store it privately.
6. Under Network Access, add your current public IP address with Add Current IP Address. A single IPv4 address is typically shown with `/32`. Wait until the entry is active. Update it if your ISP or VPN changes your public IP. Do not add `0.0.0.0/0` for this setup.
7. On the cluster, choose Connect > Drivers. Select Node.js and a supported current driver version. Mongoose uses the MongoDB driver internally; do not install another package.
8. Copy the `mongodb+srv://` connection string. Replace its username and password placeholders locally with the database user's credentials. Preserve the actual cluster hostname and Atlas query parameters. Percent-encode special characters in the username/password portions (for example, `@` becomes `%40` and `#` becomes `%23`). Do not encode the entire URI or share the result.
9. Open `backend/.env` in VS Code. Keep `PORT=4000`. Replace only the `MONGODB_URI` value with your completed connection string, surrounded by double quotes. Quotes prevent dotenv treating a password's `#` as a comment; percent-encoding is still needed for URI syntax. Leave `.env.example` unchanged. Never commit or paste your real URI into chat.

### Connection files

`src/config/constants.js` exports `DB_NAME`, the name `intro_to_backend`. A database belongs to a cluster and contains collections, which contain documents.

`src/config/database.js` imports Mongoose and the database name, then exports `connectDB`. It reads `process.env.MONGODB_URI` when called, connects with `await mongoose.connect()`, explicitly selects the database using `dbName`, and prints the database name and server host after success. The `serverSelectionTimeoutMS` option limits the server-selection wait to 10 seconds; DNS resolution may take additional time.

The URI is restricted to the Atlas SRV format used by this tutorial. The database name option avoids fragile string concatenation onto a URI containing query parameters. Connecting alone does not create user or post documents.

On failure, `catch` prints a safe explanation and throws an error. The startup caller must handle that rejection and exit with code 1. Phase 3 will await this function before starting Express. We do not print the raw URI or raw database error.

### JavaScript concepts in this phase

- `import` uses code from another module; `export` makes code available to other modules. Named exports use braces (`{ DB_NAME }`); a default export is imported without braces (`connectDB`). Relative imports include `.js`.
- `const` declares a binding we will not reassign, such as `uri`. `let` allows reassignment, used for the error explanation.
- `async () => { ... }` is an async arrow function. Calling it returns a Promise: an object representing eventual success or failure.
- `await` waits for a Promise inside an async function or, as in our verification command, at the top level of an ES Module. It does not block all Node.js activity.
- `try` groups operations that can fail. `catch (error)` handles a thrown error or rejected awaited Promise. `throw new Error(...)` rejects our async function so startup cannot proceed silently.
- `if` and `else if` choose an error explanation based on the failure. `!` means not, and `||` means or.
- `process.env` contains environment variables. Loading `dotenv/config` fills them from `.env` in the current working directory.
- `{ dbName: DB_NAME, serverSelectionTimeoutMS: 10000 }` is an object containing named connection options.
- `?.` is optional chaining: it avoids calling `startsWith` when the URI is missing. `startsWith()` checks the string prefix.
- Backticks make template strings; `${...}` inserts a value into the message.
- `console.log` prints normal messages; `console.error` prints failure messages. `process.exit(1)` ends the verification process with a failure code.

### Common connection problems

- Missing/placeholder URI: save the real Atlas URI in `backend/.env` and run the command from `backend`.
- Authentication failed: use the database user, not your Atlas sign-in; check the password and percent-encoding.
- Cannot reach Atlas: check your current public IP access-list entry, internet/VPN/firewall, and that the cluster is active.
- DNS/SRV lookup error: check the copied cluster hostname, cluster status, and whether your network can resolve Atlas SRV records.
- Invalid URI: remove leftover angle-bracket placeholders, check the `mongodb+srv://` prefix, preserve query parameters, and encode credential characters.
- Database absent in Browse Collections: expected until the first collection or document is created.

The connection code has been syntax-checked and its missing-configuration failure path verified. A successful live Atlas connection remains to be verified after the owner configures a cluster and local credentials.


## Phase 3: Express app and server setup

The files below show the final, connected project. Phase 3 imports the routers that are explained in Phases 4 and 5; all of those files are now present.

### File 1: src/app.js

This file configures Express without starting a network listener. Separating configuration from startup lets our tests inspect routes without opening an Atlas connection.

Express handles an HTTP request through middleware functions in registration order. `express.json()` parses JSON into `req.body`. Its 100 KB limit prevents unexpectedly large requests. The next middleware requires object-shaped JSON for POST/PATCH/PUT so controllers can safely destructure the body. It calls `next()` to continue, or returns a response to stop processing.

The health endpoint uses `app.get()`. `app.use('/api/v1/users', userRouter)` mounts the user router under that URL prefix. An unknown route receives JSON with status 404. The final four-argument middleware catches malformed JSON, oversized bodies, and unexpected Express errors without exposing internal details. The unused `next` argument is needed for Express to recognize the error-handler signature.


**Complete file: `backend/src/app.js`**

```javascript
import express from "express";
import userRouter from "./routes/user.route.js";
import postRouter from "./routes/post.route.js";

const app = express();

app.use(express.json({ limit: "100kb" }));

// Reject arrays and other unexpected body shapes before controllers destructure.
app.use((req, res, next) => {
  if (["POST", "PATCH", "PUT"].includes(req.method)) {
    if (!req.is("application/json")) {
      return res.status(400).json({ message: "Send Content-Type: application/json and a JSON object body." });
    }
    if (!req.body || typeof req.body !== "object" || Array.isArray(req.body)) {
      return res.status(400).json({ message: "Request body must be a JSON object." });
    }
  }
  next();
});

app.get("/", (req, res) => {
  res.status(200).json({ message: "Backend is running successfully" });
});

app.use("/api/v1/users", userRouter);
app.use("/api/v1/posts", postRouter);

app.use((req, res) => {
  res.status(404).json({ message: "Route not found." });
});

// Express recognizes error middleware by its four arguments.
app.use((error, req, res, next) => {
  if (error.type === "entity.parse.failed") {
    return res.status(400).json({ message: "Invalid JSON body. Check quotes, commas, and braces." });
  }
  if (error.type === "entity.too.large") {
    return res.status(400).json({ message: "JSON body must not exceed 100 KB." });
  }
  return res.status(500).json({ message: "An unexpected server error occurred." });
});

export default app;
```

### File 2: src/index.js

This is the entry point run by both npm scripts. `import 'dotenv/config'` loads environment variables before startup. The imported connection function reads them when it is called.

The function validates PORT, awaits MongoDB, and awaits `User.init()` before listening. Initialization waits for the username/email unique indexes: `unique: true` declares a database index, not a normal Mongoose validator. The server must not accept registrations before those indexes exist. If existing documents contain duplicates, startup fails until they are corrected in Atlas.

`app.listen()` creates the HTTP server. Its callback prints the URL after listening begins. A server `error` listener handles asynchronous failures such as an occupied port; try/catch alone would not handle that event. Failed startup disconnects Mongoose and exits with code 1.

The tiny `.catch(() => {})` during cleanup prevents a failed disconnection from replacing the original startup explanation.


**Complete file: `backend/src/index.js`**

```javascript
import "dotenv/config";
import mongoose from "mongoose";
import app from "./app.js";
import connectDB from "./config/database.js";
import User from "./models/user.model.js";

const startServer = async () => {
  try {
    const port = Number(process.env.PORT || 4000);
    if (!Number.isInteger(port) || port < 1 || port > 65535) {
      throw new Error("PORT must be an integer between 1 and 65535.");
    }

    await connectDB();
    // Wait for username/email unique indexes before accepting registrations.
    await User.init();

    const server = app.listen(port, () => {
      console.log(`Server running at http://localhost:${port}`);
    });

    server.on("error", async (error) => {
      console.error(error.code === "EADDRINUSE"
        ? `Port ${port} is already in use. Stop the other server or change PORT.`
        : "The HTTP server could not start.");
      await mongoose.disconnect().catch(() => {});
      process.exit(1);
    });
  } catch (error) {
    if (error.code === 11000) {
      console.error("Startup failed: existing duplicate users prevent unique indexes. Remove duplicates in Atlas.");
    } else if (error.message === "PORT must be an integer between 1 and 65535.") {
      console.error(error.message);
    } else {
      console.error("Startup failed. Check the database configuration, Atlas permissions, and unique indexes.");
    }
    await mongoose.disconnect().catch(() => {});
    process.exit(1);
  }
};

startServer();
```

## Phase 4: User model and authentication APIs

### File 1: src/models/user.model.js

`new mongoose.Schema()` defines field rules. `mongoose.model('User', userSchema)` creates the interface we query and save through. Mongoose normally maps User to the `users` collection.

Username and email are trimmed and lowercased so capitalization does not create separate identities. Username permits 1–30 characters; email is checked with a simple format pattern and a 254-character maximum. This checks shape, not whether an inbox actually exists. Passwords are not trimmed: spaces are part of a password. They require at least 6 JavaScript string characters and no more than 72 UTF-8 bytes because bcrypt truncates input after 72 bytes. `Buffer.byteLength()` measures bytes, which can differ from string length for non-ASCII text.

The pre-save hook runs before saving. It is a regular function because Mongoose supplies the current document through `this`; an arrow function would not receive that binding. `isModified('password')` avoids hashing an existing hash on an unrelated save. bcrypt uses a work factor of 10 and generates a salt automatically; hashing is one-way, not reversible encryption. The comparison method calls bcrypt to check a submitted password against the stored hash.

`select: false` hides the hash from ordinary queries. Login explicitly selects it for comparison. The JSON transform deletes it even from an explicitly selected document; controllers additionally return only three allowed user fields. Timestamps automatically maintain `createdAt` and `updatedAt`.


**Complete file: `backend/src/models/user.model.js`**

```javascript
import mongoose from "mongoose";
import bcrypt from "bcrypt";

const userSchema = new mongoose.Schema(
  {
    username: {
      type: String,
      required: true,
      unique: true,
      lowercase: true,
      trim: true,
      minlength: 1,
      maxlength: 30,
    },
    email: {
      type: String,
      required: true,
      unique: true,
      lowercase: true,
      trim: true,
      maxlength: 254,
      match: /^[^\s@]+@[^\s@]+\.[^\s@]+$/,
    },
    password: {
      type: String,
      required: true,
      minlength: 6,
      select: false,
      // bcrypt only uses the first 72 bytes of a password.
      validate: {
        validator: (value) => Buffer.byteLength(value, "utf8") <= 72,
        message: "Password must be at most 72 UTF-8 bytes.",
      },
    },
  },
  { timestamps: true },
);

// Use a regular function because Mongoose supplies the document as `this`.
userSchema.pre("save", async function () {
  if (!this.isModified("password")) return;
  this.password = await bcrypt.hash(this.password, 10);
});

userSchema.methods.comparePassword = async function (submittedPassword) {
  return bcrypt.compare(submittedPassword, this.password);
};

// Defense in depth: even explicitly selected hashes are removed from JSON.
userSchema.set("toJSON", {
  transform: (document, returnedObject) => {
    delete returnedObject.password;
    return returnedObject;
  },
});

const User = mongoose.model("User", userSchema);

export default User;
```

### File 2: src/controllers/user.controller.js

Each exported controller is an async Express handler. `req` represents the incoming request; `res` builds the outgoing response. `const { username, email, password } = req.body` is destructuring: it reads named properties into variables. `typeof` prevents Mongoose from silently converting unintended input types.

Registration normalizes username/email, validates lengths, then uses `findOne()` with MongoDB's `$or` to find either duplicate. `User.create()` validates and saves a document and runs the password hook. MongoDB error 11000 is also handled because two simultaneous requests could both pass the initial duplicate check. A successful response contains _id, username, and email only.

Login checks the input, selects the hash using `.select('+password')`, and calls the model's password comparison method. A validly shaped request with an unknown email or wrong password gets the same 401 message. Malformed inputs get 400. Successful login returns user details and creates no cookie, token, or session. No JWT library is installed.

Logout accepts an email and checks whether the user exists. It only returns a demonstration message: there is no authentication state to revoke and no document is modified. This endpoint also reveals whether an email exists, which is another reason to keep this tutorial separate from a production authentication system.

The controller builds explicitly allowed user fields when creating records. Extra registration/login/logout properties are ignored; post create/update rejects unknown fields. Each catch returns a safe message rather than a raw database error or stack trace.


**Complete file: `backend/src/controllers/user.controller.js`**

```javascript
import User from "../models/user.model.js";

const emailPattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

export const registerUser = async (req, res) => {
  try {
    const { username, email, password } = req.body;

    if (username === undefined || email === undefined || password === undefined) {
      return res.status(400).json({ message: "Username, email, and password are required." });
    }

    if (typeof username !== "string" || typeof email !== "string" || typeof password !== "string") {
      return res.status(400).json({ message: "Username, email, and password must be strings." });
    }

    const normalizedUsername = username.trim().toLowerCase();
    const normalizedEmail = email.trim().toLowerCase();

    if (normalizedUsername.length < 1 || normalizedUsername.length > 30) {
      return res.status(400).json({ message: "Username must contain 1 to 30 characters." });
    }

    if (normalizedEmail.length > 254 || !emailPattern.test(normalizedEmail)) {
      return res.status(400).json({ message: "Provide a valid email address of at most 254 characters." });
    }

    if (password.length < 6 || Buffer.byteLength(password, "utf8") > 72) {
      return res.status(400).json({ message: "Password must contain at least 6 characters and at most 72 UTF-8 bytes." });
    }

    const existingUser = await User.findOne({
      $or: [{ username: normalizedUsername }, { email: normalizedEmail }],
    });

    if (existingUser) {
      return res.status(409).json({ message: "Username or email is already registered." });
    }

    // The model's pre-save hook hashes the password before MongoDB receives it.
    const user = await User.create({
      username: normalizedUsername,
      email: normalizedEmail,
      password,
    });

    return res.status(201).json({
      message: "User registered successfully.",
      user: { _id: user._id, username: user.username, email: user.email },
    });
  } catch (error) {
    // Two simultaneous registrations can pass findOne; the unique indexes decide.
    if (error.code === 11000) {
      return res.status(409).json({ message: "Username or email is already registered." });
    }
    if (error.name === "ValidationError") {
      return res.status(400).json({ message: "Invalid user data. Check username, email, and password." });
    }
    return res.status(500).json({ message: "Unable to register user. Please try again later." });
  }
};

export const loginUser = async (req, res) => {
  try {
    const { email, password } = req.body;

    if (typeof email !== "string" || typeof password !== "string") {
      return res.status(400).json({ message: "Email and password are required and must be strings." });
    }

    const normalizedEmail = email.trim().toLowerCase();
    if (!emailPattern.test(normalizedEmail) || normalizedEmail.length > 254) {
      return res.status(400).json({ message: "Provide a valid email address of at most 254 characters." });
    }

    if (password.length < 6 || Buffer.byteLength(password, "utf8") > 72) {
      return res.status(400).json({ message: "Password must contain at least 6 characters and at most 72 UTF-8 bytes." });
    }

    // Only login needs the stored hash; ordinary queries exclude it.
    const user = await User.findOne({ email: normalizedEmail }).select("+password");
    if (!user || !(await user.comparePassword(password))) {
      return res.status(401).json({ message: "Invalid email or password." });
    }

    return res.status(200).json({
      message: "Credentials verified. No persistent session was created.",
      user: { _id: user._id, username: user.username, email: user.email },
    });
  } catch {
    return res.status(500).json({ message: "Unable to log in. Please try again later." });
  }
};

export const logoutUser = async (req, res) => {
  try {
    const { email } = req.body;
    if (typeof email !== "string") {
      return res.status(400).json({ message: "Email is required and must be a string." });
    }

    const normalizedEmail = email.trim().toLowerCase();
    if (!emailPattern.test(normalizedEmail) || normalizedEmail.length > 254) {
      return res.status(400).json({ message: "Provide a valid email address of at most 254 characters." });
    }

    const user = await User.findOne({ email: normalizedEmail });
    if (!user) {
      return res.status(404).json({ message: "User not found." });
    }

    return res.status(200).json({
      message: "Simulated logout successful. No session or token was revoked.",
    });
  } catch {
    return res.status(500).json({ message: "Unable to simulate logout. Please try again later." });
  }
};
```

## Phase 5: Post model and CRUD APIs

### File 1: src/models/post.model.js

A Post stores a character's name, description, and numeric age from 0 to 150. Whitespace-only names/descriptions are rejected, and leading/trailing whitespace is removed. Decimal ages within the range are allowed; this tutorial does not require whole numbers. Zero is valid, so the controller must not use `if (!age)` to check presence.

Mongoose normally prepares an ObjectId `_id` for a new document before inserting it. MongoDB requires the _id field and generates one if a client omits it. In API JSON it appears as a 24-character hexadecimal string. Keep it for update/delete requests. `__v`, which you may see in responses, is Mongoose's version key.


**Complete file: `backend/src/models/post.model.js`**

```javascript
import mongoose from "mongoose";

const postSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: true,
      trim: true,
    },
    description: {
      type: String,
      required: true,
```

### File 2: src/controllers/post.controller.js

CREATE validates the body before `Post.create()`. READ uses `Post.find()`, returning an array in `posts`; an empty database returns `{ "posts": [] }` with 200, not 404.

UPDATE reads `req.params.id`, the value captured by `:id` in the URL. `mongoose.isObjectIdOrHexString()` requires an ObjectId or a 24-character hex string; URL values are strings. A well-formed ID can still identify no document, so null results get 404.

`Object.keys(req.body)` returns an array of field names. `.some()` tests whether at least one key is invalid, while `.includes()` checks whether a field is allowed or present. The code rejects an empty patch, unknown fields, MongoDB operators supplied by the client, and invalid values. It constructs a fresh `updates` object with only allowed values.

`findByIdAndUpdate()` receives `{ $set: updates }`, preserving omitted fields. `new: true` returns the updated document and `runValidators: true` applies schema validation to the update. Timestamp handling updates updatedAt. DELETE uses `findByIdAndDelete()` and handles null the same way.

Every CRUD endpoint is public. Login does not protect any route. Production applications would normally authenticate callers, check ownership/authorization for writes, and add further operational controls; none of those are implemented here.

```javascript
import mongoose from "mongoose";
import Post from "../models/post.model.js";

export const createPost = async (req, res) => {
  try {
    const allowedFields = ["name", "description", "age"];
    if (Object.keys(req.body).some((field) => !allowedFields.includes(field))) {
      return res.status(400).json({ message: "Only name, description, and age are allowed." });
    }

    const { name, description, age } = req.body;
    if (name === undefined || description === undefined || age === undefined) {
      return res.status(400).json({ message: "Name, description, and age are required." });
    }

    if (typeof name !== "string" || name.trim().length === 0 || typeof description !== "string" || description.trim().length === 0) {
      return res.status(400).json({ message: "Name and description must be non-empty strings." });
    }

    if (typeof age !== "number" || !Number.isFinite(age) || age < 0 || age > 150) {
      return res.status(400).json({ message: "Age must be a number between 0 and 150." });
    }

    const post = await Post.create({ name: name.trim(), description: description.trim(), age });
    return res.status(201).json({ message: "Post created successfully.", post });
  } catch (error) {
    if (error.name === "ValidationError") {
      return res.status(400).json({ message: "Invalid post data. Check name, description, and age." });
    }
    return res.status(500).json({ message: "Unable to create post. Please try again later." });
  }
};

export const getPosts = async (req, res) => {
  try {
    const posts = await Post.find();
    return res.status(200).json({ posts });
  } catch {
    return res.status(500).json({ message: "Unable to retrieve posts. Please try again later." });
  }
};

export const updatePost = async (req, res) => {
  try {
    const { id } = req.params;
    if (!mongoose.isObjectIdOrHexString(id)) {
      return res.status(400).json({ message: "Invalid post ID. Use a 24-character hexadecimal MongoDB ID." });
    }

    const fields = Object.keys(req.body);
    const allowedFields = ["name", "description", "age"];

    if (fields.length === 0) {
      return res.status(400).json({ message: "Provide at least one field to update." });
    }
    if (fields.some((field) => !allowedFields.includes(field))) {
      return res.status(400).json({ message: "Only name, description, and age can be updated." });
    }

    const updates = {};

    if (fields.includes("name")) {
      if (typeof req.body.name !== "string" || req.body.name.trim().length === 0) {
        return res.status(400).json({ message: "Name must be a non-empty string." });
      }
      updates.name = req.body.name.trim();
    }

    if (fields.includes("description")) {
      if (typeof req.body.description !== "string" || req.body.description.trim().length === 0) {
        return res.status(400).json({ message: "Description must be a non-empty string." });
      }
      updates.description = req.body.description.trim();
    }

    if (fields.includes("age")) {
      const { age } = req.body;
      if (typeof age !== "number" || !Number.isFinite(age) || age < 0 || age > 150) {
        return res.status(400).json({ message: "Age must be a number between 0 and 150." });
      }
      updates.age = age;
    }

    const post = await Post.findByIdAndUpdate(
      id,
      { $set: updates },
      { new: true, runValidators: true },
    );

    if (!post) {
      return res.status(404).json({ message: "Post not found." });
    }
    return res.status(200).json({ message: "Post updated successfully.", post });
  } catch (error) {
    if (error.name === "ValidationError") {
      return res.status(400).json({ message: "Invalid post data. Check name, description, and age." });
    }
    return res.status(500).json({ message: "Unable to update post. Please try again later." });
  }
};

export const deletePost = async (req, res) => {
  try {
    const { id } = req.params;
    if (!mongoose.isObjectIdOrHexString(id)) {
      return res.status(400).json({ message: "Invalid post ID. Use a 24-character hexadecimal MongoDB ID." });
    }

    const post = await Post.findByIdAndDelete(id);
    if (!post) {
      return res.status(404).json({ message: "Post not found." });
    }

    return res.status(200).json({ message: "Post deleted successfully." });
  } catch {
    return res.status(500).json({ message: "Unable to delete post. Please try again later." });
  }
};
```

## MVC-style structure and request flow

Models define data. Routes define URL/method mappings. Controllers coordinate input, model calls, and JSON responses. This is MVC-style rather than a full server-rendered MVC application: there is no HTML view layer; JSON is the output.

```text
Postman (client)
  -> Express app.js (parse JSON, choose router)
  -> Router (match method and URL)
  -> Controller (validate and handle request)
  -> Mongoose Model (validate/hash/query)
  -> MongoDB Atlas (store or retrieve documents)
  -> Controller -> JSON response -> Postman
```

For registration, Postman sends POST /api/v1/users/register with JSON. app.js parses it and selects userRouter. user.route.js calls registerUser. The controller validates, normalizes, and checks User.findOne. User.create invokes schema validation and the pre-save bcrypt hook, then inserts into Atlas. The controller sends 201 with a safe user object. An error stops that path and sends an appropriate response instead.

## HTTP fundamentals

- **GET:** Read a resource. Our GET request needs no body and does not change documents.
- **POST:** Submit data for processing, such as registration, credential checks, or creation. Repeating a create request may create another record.
- **PUT:** Conventionally replace the complete editable representation of a resource. This project provides no PUT endpoint.
- **PATCH:** Change selected fields. Our PATCH preserves fields omitted from the JSON.
- **DELETE:** Remove a resource. A repeated delete of the same post returns 404 after the first succeeds; the post remains absent.

Status codes used in this project:

- **200 OK:** A read, login check, simulated logout, update, or delete succeeded.
- **201 Created:** A user or post was created.
- **400 Bad Request:** Missing/invalid fields, malformed JSON, invalid IDs, or unsupported request-body shape.
- **401 Unauthorized:** A validly shaped login request has invalid credentials.
- **404 Not Found:** No route, user for demonstration logout, or requested post exists.
- **409 Conflict:** A username or email is already registered.
- **500 Internal Server Error:** An unexpected server/database operation failed. API users receive a safe explanation.

In `http://localhost:4000/api/v1/posts/get`, `http` is the protocol, `localhost` means this computer, `4000` is the listening port, and the rest is the route path. Atlas is a separate remote database service; your client calls Express, not Atlas directly.

HTTP carries requests/responses. HTTPS adds encryption and server identity verification through TLS. This local tutorial uses HTTP on localhost; a deployed API handling passwords needs HTTPS. The Atlas driver connection separately uses TLS by default with its SRV URI.

Headers describe a request or response. `Content-Type: application/json` tells Express how to interpret the request body; `Accept: application/json` says the client prefers a JSON response. JSON requires double-quoted keys/strings, does not allow comments or trailing commas, and distinguishes numbers (20) from strings ("20"). Express's `res.status(...).json(...)` sets the status and serializes the response as JSON.

### Common errors and fixes

- **Cannot find package:** run npm install from backend.
- **Cannot use import outside a module:** confirm backend/package.json has type=module and you are running files from this project.
- **ERR_MODULE_NOT_FOUND:** check spelling, relative paths, and .js extensions.

**Complete file: `backend/src/config/database.js`**

```javascript
import mongoose from "mongoose";
import dns from "node:dns";
import { DB_NAME } from "./constants.js";

const connectDB = async () => {
  try {
    const uri = process.env.MONGODB_URI;

    if (!uri || !uri.startsWith("mongodb+srv://")) {
      throw new Error("An Atlas connection string is required.");
    }

    if (/[<>]|%3c(?:db_password|password|username|db_username)%3e/i.test(uri)) {
      throw new Error("Replace the Atlas connection string placeholders.");
    }

    // Optional workaround for networks that refuse Atlas SRV DNS lookups.
    // This affects this Node.js process only, not the computer's DNS settings.
    if (process.env.MONGODB_DNS_SERVERS) {
      dns.setServers(process.env.MONGODB_DNS_SERVERS.split(",").map((server) => server.trim()));
    }

    const connection = await mongoose.connect(uri, {
      dbName: DB_NAME,
      serverSelectionTimeoutMS: 10000,
    });

    console.log(`MongoDB connected successfully: ${DB_NAME}`);
    console.log(`MongoDB host: ${connection.connection.host}`);
  } catch (error) {
    let message = "Check your Atlas cluster, connection string, and network access.";

    if (!process.env.MONGODB_URI?.startsWith("mongodb+srv://")) {
      message = "Set MONGODB_URI in backend/.env to your Atlas mongodb+srv:// connection string.";
    } else if (/[<>]|%3c(?:db_password|password|username|db_username)%3e/i.test(process.env.MONGODB_URI)) {
      message = "Replace the Atlas username/password placeholders in backend/.env, remove angle brackets, and encode special credential characters.";
    } else if (error.code === 18 || (error.name === "MongoServerError" && /bad auth|authentication failed|authentication failure/i.test(error.message))) {
      message = "Atlas authentication failed. Check your database username and password.";
    } else if (error.name === "MongoParseError") {
      message = "The MongoDB URI is invalid. Check its format and encode special password characters.";
    } else if (["ENOTFOUND", "ENODATA", "ECONNREFUSED", "ETIMEOUT", "ESERVFAIL", "EAI_AGAIN"].includes(error.code)) {
      message = `Atlas DNS lookup failed (${error.code}). Check the cluster hostname and your network's DNS settings.`;
    } else if (error.name === "MongooseServerSelectionError") {
      message = "Atlas could not be reached. Check Network Access, your internet connection, and cluster status.";
    }

    // Do not print the connection string or raw errors containing credentials.
    console.error(`MongoDB connection failed: ${message}`);

    // The caller must stop startup instead of starting a server without a database.
    throw new Error("Database startup failed. Fix the configuration and try again.");
  }
};

export default connectDB;
```
